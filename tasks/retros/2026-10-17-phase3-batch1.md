## What cost the most and why
1. **Exemplar memory, 2 review rounds.** A scrubber is a rule list; the first review found
   leaks (company short forms, hyphenated surnames, honorifics, lowercase cities), the
   second found the case gate also covered cities. Fixed with a fail-closed invariant
   (drop the exemplar if any distinctive token survives) + a property test. Same lesson
   as the simulation (G13): invariant in code, not a longer regex. Reviewer cost at hub
   rigor (~114k + ~142k tokens) was justified: these leaks would have sent one prospect's
   company name to another.
2. **Two workers wrote the same wrong lookup.** Both pipeline-ui and calendar-sync
   picked "latest sent pitch", which is a follow-up child, not the root. The conductor
   landed `latestRootSentPitchId()` after the first review; the second worker had
   branched before it. Rule: scan briefs for shared lookups and land them in wave 0.
3. **Wave 0 missed the TS unions** for the enum values migration 0043 added; the first
   worker had to work around it. Rule: a migration adding enum values ships with its
   TS union in the same conductor commit.
4. **Brief contradiction** (contact-source-url): the brief asserted a fetch order the
   code does not have. The worker caught it. Rule: verify any claim about code order
   or behaviour with a grep before it goes in a brief.
